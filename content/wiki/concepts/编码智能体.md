## 定义

自主执行软件开发任务的 AI 智能体（写代码、代码审查、提 PR、解答工程问题等），2026 年成为软件团队产出加速的主要引擎，并重塑"谁在写代码"的团队结构。

## 关键信息

- **规模数据**（[[Linear]] 报告，2026-08）：AI 创作近一半 issue（两年前不足千分之一）；PR 总量两年 +111%；接入编码 agent 的团队周 PR 从 21 增至 65（未接入者 8→10）；产品经理提 PR 比例 3%→10%、设计师 1%→8%——"描述变更的人开始自己交付变更"。
- **成本经济学**（Unblocked，2026-08）：从 Claude Opus 迁至 [[GLM-5.3]] 同系的开源权重 GLM 5.2 后，代码审查单任务成本降 68%（按 token 单价宣称 95%）；关键教训是**按任务算成本而非按 token**——GLM 更爱探索、更多试错、每任务 token 高约 1/3。
- **工程现实**："OpenAI-compatible" API 是光谱而非标准：reasoning 字段、缓存键、结构化输出、用量统计各家不一，需一致性测试套件与多供应商池化（断路器+自适应路由），Claude 保留为兜底与合规池。
- **评估方法**：生产环境双管道盲测（同一 PR 两个模型同时审查、用户情绪投票）比公共基准更能指导选型；模型选择从一次性决策变成持续运营的系统。
- **成瘾与倦怠风险**（2026-08-21，Coddy/ZDNet）：305 名开发者调查中 80% 认为 AI 使用"更像依赖而非优势"；43% 下班后停不下来、32% 推迟睡眠、39% 更难"关机"；74% 认为重度使用提升升职加薪概率，但 51% 更可能 burnout（"agentic coding 是上瘾的——做对给多巴胺、失败给肾上腺素"）；Stack Overflow 数据显示对 AI 准确率信任降至 29%。
- **验证债务**（verification debt）：AI 输出快但开发者仍需核实正确性/安全性/可维护性——"产出变快，工作量只是转移"；雇主若把 AI 当产能倍增器，个体节省时间会被系统吞掉。
- **编排层之争**（2026-08）：NVIDIA AVO 研究显示 harness（编排层）比模型本身更影响长程任务表现（见 [[AgentHarness]]）；Netic 语音 agent 案例则证明"单模型+全上下文"可取代重型图编排（223 节点→单模型，containment +15 点）。
- **相关模型**：Claude Opus、GPT 系、GLM 5.2/5.3 均为主力；[[llama.cpp]] 代表本地推理基础设施选项。
- **专用形态**（2026-08-21）：[[摘要-autolith-lisp-agent]] 展示一种带实时运行时的 Common Lisp 编程智能体（可热替换运行中代码、append-only 变更日志），与主流"对话式 agent + 通用工具"形态不同。

# 摘要：Netic——用单个开源 LLM 替换 223 节点智能体图，语音 agent 转化率 +15 点

> 来源：Netic 工程博客（Ajay Arora，2026-08-20）。原文见 `raw/01-articles/ai-news-2026-08-22-netic-agent-graph.md`

## 核心摘要

- **背景**：Netic 为家电/管道等必需服务业做 AI 语音 agent（自动接单/预约），2024 年起把标准作业程序（SOP）编码为对话图——最终膨胀到 **223 节点、646 边** + 一堆意图/分类器节点，修修补补两年后不可持续。
- **转折**：Kimi K2.6 与 GLM 5.2 等开源权重旗舰模型发布后，一次性把"所有子 agent 提示词 + 路由规则 + 全部 SOP"拼进单个 prompt 做实验，发现单 agent 反而能处理图结构搞不定的临场修正。
- **新架构四原则**：① **约束结果而非路径**（确定性只放在工具边界/不可逆动作处，对话不预设形状）；② **模型看到一切**（完整对话历史 + 相关 SOP 全在上下文，图时代失败多半是"上下文饥饿"）；③ **指令优于原语**（策略用自然语言陈述，不再枚举每条边）；④ **一对话一 agent**（上下文不跨专家碎片化，没有 handoff 可出错）。
- **图架构四大失败机制**：过早分类（信息最少时做承诺）、节点上下文隔离（回答被另一个节点持有）、枚举式维护（每条新边都是新故障点）、子 agent 系统是"粗粒度图"（handoff 需摘要、专科 agent 无法自识别卡死——例：取消专家把同一工具调了 25 次）。
- **结果**：containment（不转人工的完成率）与可预约电话的预定率各 **+15 点**；首 token 延迟从 >1s 降到 ~500ms；新客户上线从数天缩到 1 小时；累计为客户完成 **$500M+** 自主预约。
- **工程取舍**：自建专有 harness（程序库管理、上下文装载决策、不可逆动作门禁、回归评测），"从约束模型转向供给模型（provisioning）"；开源权重 + 自持推理是满足语音延迟预算的前提。
